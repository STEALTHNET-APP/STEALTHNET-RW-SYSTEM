# Установка, обновление и резервные копии

## Что нужно

- Сервер на Linux с Docker. Если Docker нет, установщик предложит поставить его сам (при запуске от root) или покажет команду.
- Основной домен сервиса, например `example.com`, направленный на этот сервер (A-запись `@` с адресом сервера). Ставьте панель на основной домен, а не на поддомен вроде `panel.example.com`: на нём откроется лендинг, а админка и кабинет — на `example.com/admin` и `example.com/cabinet`. Без домена установка тоже пройдёт, домен можно указать позже командой `stealthnet domain`.
- Свободные и открытые снаружи порты 80 и 443, если сертификат должен выпустить установщик. Файрвол на сервере (ufw или firewalld) установщик проверит сам и предложит открыть порты, а в установке без вопросов покажет команду (`SN_OPEN_PORTS=1` открывает их без вопроса). Файрвол в панели хостинга проверьте сами. Если их держит другая программа, например nginx панели Remnawave, читайте ниже «Порты 80 и 443 заняты».

Готовая сборка выпускается для процессоров x86_64. На ARM установщик соберёт систему из исходников, это 10–20 минут.

## Установка

Скопируйте команду целиком и выполните на сервере:

```sh
git clone https://github.com/STEALTHNET-APP/STEALTHNET-RW-SYSTEM.git && STEALTHNET-RW-SYSTEM/install.sh
```

Установщик спросит основной домен и почту владельца. Дальше он сам:

1. создаст пароль базы и ключ шифрования и запишет их в `deploy/.env`;
2. скачает готовую сборку и запустит панель и базу в Docker;
3. выпустит сертификат HTTPS для домена (Caddy, продлевается сам);
4. создаст владельца и покажет адреса сайта, админки и кабинета, почту и пароль.

Пароль владельца показывается один раз, сохраните его. Повторный запуск `install.sh` продолжает установку и ничего не перезаписывает.

Установка без вопросов, например из своего скрипта:

```sh
SN_OWNER_EMAIL=owner@example.com SN_DOMAIN=example.com STEALTHNET-RW-SYSTEM/install.sh
```

Собрать из исходников вместо готовой сборки: `SN_BUILD=1 STEALTHNET-RW-SYSTEM/install.sh`.

### Что установщик решает сам

- Порт 8080 занят — берёт следующий свободный, до 8099, и показывает его в конце. Панель слушает только `127.0.0.1`, снаружи её видно через HTTPS.
- На сервере уже стоит Remnawave — подключает панель к сети `remnawave-network`. Тогда в «Настройки → Remnawave» адрес панели — `http://remnawave:3000`, а защиту eGames указывать не нужно: запросы идут к Remnawave напрямую, мимо nginx и Caddy.
- Установка от root на сервере с systemd — ставит помощника на сервере. Через него обновляют панель из админки и ставят модули из архива. Без помощника обновление делается командой `stealthnet update`, а модули — только с файлом описания, см. [модули](modules.md#внешние-модули).
- `www.example.com` указывает на этот же сервер (такая же A-запись или CNAME на основной домен) — включает переадресацию с www на основной домен. Если записи для www нет, в конце подскажет, что добавить; после этого выполните `stealthnet domain` ещё раз. Для поддомена www не предлагается. В установке без вопросов `SN_WWW=0` выключает переадресацию, а `SN_WWW=1` включает её, не дожидаясь записи.

### Дополнительные домены

Если у сервиса есть старые или запасные домены, их можно перевести на панель: все адреса на них переадресуются на основной домен с тем же путём. Направьте домены на этот сервер, впишите их через пробел в `deploy/.env` и перезапустите панель:

```
SN_SITE_ALIASES=old-example.com www.old-example.com example.online
```

```bash
stealthnet restart
```

Сертификаты для них Caddy выпустит сам. Работает, когда HTTPS держит встроенный Caddy; со своим веб-сервером переадресацию настройте в нём.

### Порты 80 и 443 заняты

Если порты держит другая программа, установщик ничего в ней не меняет. Он кладёт в `deploy/proxy-snippet.txt` готовый блок для Caddy и nginx и в конце говорит об этом. Добавьте блок в свою программу и перезагрузите её. Если включена переадресация с www, в файле есть и блок для `www.example.com`.

В блоке для nginx уже есть `client_max_body_size 20g` и `proxy_request_buffering off`, чтобы при переносе копия старого бота до 20 ГБ шла сразу в панель, без промежуточной копии у nginx, и заголовок `X-Forwarded-For`. Если в журнале входов и у клиентов вместо их адресов виден адрес прокси, настройте `SN_TRUSTED_PROXIES` (см. [переменные окружения](../../README.md#переменные-окружения)).

### HSTS и CSP

Заголовки безопасности панель ставит сама, в Caddy и nginx ничего добавлять не нужно.

- **HSTS.** На запросы по HTTPS панель отвечает заголовком `Strict-Transport-Security: max-age=31536000`: год браузер открывает домен панели только по HTTPS, даже если набрать `http://`. Поддомены правило не затрагивает. HTTPS панель узнаёт по заголовку `X-Forwarded-Proto`: Caddy передаёт его сам, в блоке для nginx из `deploy/proxy-snippet.txt` он тоже есть. Правило действует для домена на всех портах. Если на этом же домене на другом порту что-то работает без HTTPS, добавьте в `deploy/.env` строку `SN_HSTS_MAX_AGE=0` и выполните `stealthnet restart`: браузеры забудут правило при следующем заходе.
- **CSP.** Политика говорит браузеру, откуда странице можно загружать скрипты, стили, картинки и фреймы. В админке она действует сразу: скрипт, внедрённый в страницу, браузер не выполнит. На лендинге, в кабинете, в мини-приложении и на странице оплаты политика пока работает в режиме отчётов: браузер ничего не блокирует, а о нарушении сообщает панели. В журнале (`stealthnet logs`) появляется строка «CSP: браузер сообщил о нарушении политики страницы» с адресом ресурса и страницей.
- Если вы добавляете на страницы чужие скрипты через свой прокси или Cloudflare (счётчики, Web Analytics, Rocket Loader, Zaraz), с включённой политикой они работать перестанут. Строки в журнале покажут это заранее.
- Включить политику на всех страницах: `SN_CSP=all` в `deploy/.env` и `stealthnet restart`. Оставить только отчёты и в админке: `SN_CSP=report`.
- Капча Cloudflare Turnstile или Яндекс SmartCaptcha из модуля «Антибот» в политику добавляется сама: пока капча выбрана, домен её сервиса разрешён на лендинге, в кабинете, мини-приложении и странице проверки.
- Свой CSS лендинга и мини-приложения отдаётся отдельными файлами с домена панели, политика их пропускает: менять для них ничего не нужно.

## Команда `stealthnet`

После установки команда работает из любой папки. Если поставить её не удалось (нет прав на `/usr/local/bin`), установщик покажет те же действия с полным путём: `STEALTHNET-RW-SYSTEM/install.sh --update` и т. д.

| Команда | Что делает |
|---|---|
| `stealthnet` | Установить или продолжить установку |
| `stealthnet domain` | Указать или сменить домен панели |
| `stealthnet cert`, `stealthnet cert --force` | Выпустить сертификат HTTPS заново, если он не выпустился: показывает, куда указывает домен, сразу повторяет выпуск и называет причину, если не вышло; с `--force` заменяет уже выпущенный |
| `stealthnet owner-email` | Сменить почту владельца, пароль остаётся прежним |
| `stealthnet reset-password` | Выдать владельцу новый пароль, все его сессии закрываются |
| `stealthnet unlock-login`, `stealthnet unlock-login --ip <адрес>` | Снять блокировку входа владельца, если его почту подбирают. С `--ip` вход с этого адреса не закроется 30 дней, даже пока подбор идёт |
| `stealthnet update` | Скачать новую версию и обновить систему |
| `stealthnet status` | Показать версию, адрес панели (или что он не задан), состояние панели и итог последнего обновления |
| `stealthnet helper on`, `stealthnet helper off` | Разрешить или запретить обновление из админки и установку модулей из архива |
| `stealthnet modules`, `stealthnet modules on`, `stealthnet modules off` | Показать модули из архива и их состояние; разрешить или запретить ставить их и управлять ими из админки. Уже поставленные модули после запрета продолжают работать |
| `stealthnet start`, `stealthnet restart`, `stealthnet stop` | Запустить (например, после перезагрузки сервера), перезапустить или остановить систему |
| `stealthnet logs`, `stealthnet logs -f` | Последние строки журнала панели; с `-f` — следить |
| `stealthnet backup` | Сделать резервную копию сейчас |
| `stealthnet restore файл`, `stealthnet restore --yes файл` | Восстановить базу из резервной копии, см. [восстановление](#восстановление) |

## Обновление

### Из админки

Через пару минут после обновления и дальше каждые 6 часов панель спрашивает у реестра сборок GitHub, вышла ли новая версия. Когда вышла, строка версии в меню админки предлагает обновиться, у «Настроек» появляется точка, а в «Настройки → Обновления» — кнопка обновления.

Обновляет только владелец: панель ещё раз спрашивает пароль и, если включён вход по коду, код из приложения. Шаги видны на экране: «Проверка сборки», «Загрузка», «Резервная копия», «Обновление базы», «Запуск новой версии», «Проверка работы». Панель и бот недоступны около минуты, страницу можно не закрывать — она продолжит сама.

Само приложение Docker не трогает: оно кладёт заявку, а обновляет помощник на сервере. Поэтому на экране может появиться просьба выполнить команду. Панель просит только эти команды: `sudo stealthnet status`, `sudo stealthnet update`, `sudo stealthnet helper on` и `sudo stealthnet modules on`. Другие команды от имени панели не выполняйте.

Обновление из админки меняет только сборку панели, сам установщик на сервере остаётся прежним. Если сервер давно обновлялся только из админки, а страница установки модуля просит обновить помощника, выполните один раз `sudo stealthnet update`.

### Командой

```sh
sudo stealthnet update
```

Команда идёт тем же путём, что и админка. Ею можно обновляться всегда, даже если обновление из админки выключено.

### Что происходит при обновлении

1. Скачивается новая сборка, проверяется её номер.
2. Панель останавливается, сохраняется копия базы и файла `deploy/.env`.
3. Новая версия обновляет копию базы, затем копия становится рабочей базой.
4. Запускается новая версия, 90 секунд проверяется, что отвечают панель, бот и фоновые задачи.

Если сбой случился до запуска новой версии, возвращается прежняя версия на нетронутой базе. После запуска база назад сама не возвращается: за это время могли прийти оплаты. В таком случае `stealthnet status` и экран обновлений покажут, что случилось и что делать.

Проверку обновлений можно выключить в том же экране или переменной `SN_UPDATE_CHECK=false` — например, если у сервера нет выхода в интернет.

## Резервные копии

Раздел «Настройки → Резервные копии». Открыт владельцу и администраторам, которым владелец включил право «Резервные копии» в «Администраторах».

### Что в копии

- Вся база: клиенты, подписки, оплаты, балансы, промокоды, рефералы, обращения, настройки, тексты и картинки бота, файлы сайта.
- Отдельный снимок подписок с их пользователями Remnawave на момент копии: id, ссылка (shortUuid), имя, срок, лимиты трафика и устройств, сквады, статус. Он нужен, чтобы вернуть подписки, даже если Remnawave потеряла данные. Если Remnawave не ответила, снимок собирается по данным панели.
- Сразу после записи панель читает файл целиком и сверяет контрольные суммы и число строк в каждой таблице. Копия, не прошедшая проверку, не сохраняется, а админам приходит уведомление.

Копия делается без остановки панели и бота. Файл — обычный `tar.gz` (с паролем — `tar.gz.enc`).

### Пароль копий

Задаётся на вкладке «Настройки». С паролем копия зашифрована, и в неё кладётся ключ шифрования секретов `SN_SECRET_KEY`: на другом сервере ключи платёжек, токен бота и другие секреты восстановятся. Без пароля ключа в копии нет — при восстановлении на сервере с другим ключом панель честно предупредит, что секреты придётся ввести заново, и выключит вход по коду у администраторов и клиентов.

Пароль, отправку в Telegram и S3 меняют, ещё раз введя свой пароль (и код из приложения, если он включён). Забытый пароль копий не восстановить: запишите его там, где храните другие пароли.

### Когда и куда

- Расписание: каждые 1–12 часов, каждый день или раз в неделю, по часовому поясу панели. По умолчанию — каждый день в 04:00. Если сервер был выключен во время копии, она сделается после запуска. «Сделать копию сейчас» — в любой момент, или командой `sudo stealthnet backup`.
- На сервере: папка `deploy/backups/panel`, хранится столько последних копий, сколько задано (по умолчанию 7). Старая удаляется только после новой удачной. Если панель запущена без Docker, копии лежат в папке из переменной `SN_BACKUP_DIR`: без неё раздел так и подскажет, а копии не делаются.
- Скачать — кнопкой «Скачать» в списке: панель попросит ваш пароль (и код из приложения, если он включён), после этого начнётся загрузка. Каждое скачивание пишется в журнал действий.
- Telegram: в группу уведомлений, тема «Резервные копии», или в другой чат или канал по номеру (бот должен быть в нём администратором). Копию больше 45 МБ бот присылает частями `имя.part001`, `имя.part002`…; собрать: `cat имя.part* > имя`.
- S3: любое S3-совместимое хранилище — адрес, регион, бакет, папка, ключ доступа и секретный ключ, с кнопкой «Проверить подключение». Старые копии в хранилище панель не удаляет — настройте срок хранения правилом жизненного цикла бакета.

Неудачная копия или отправка приходит уведомлением в группу администраторов (вид «Резервные копии»), в списке копий рядом появляется «Отправить ещё раз».

### Восстановление

В админке: «Восстановить» у копии в списке или вкладка «Восстановление», чтобы загрузить файл (части из Telegram можно выбрать все сразу).

1. Панель проверяет файл, ничего не меняя: дата, версия, сколько клиентов, подписок и оплат, что будет с ключами.
2. После подтверждения своим паролем панель приостанавливает бота, воркер и приём оплат (на запросы панель и платёжки получают ответ «идёт восстановление»), сохраняет копию текущей базы и заменяет данные одной операцией: при любой ошибке база остаётся прежней.
3. Копия старой версии обновляется до текущей теми же обновлениями базы, что и при обычном обновлении панели.

После восстановления пароли администраторов становятся такими, как в копии. Если Remnawave потеряла пользователей или сроки в ней расходятся с панелью, перенесите клиентов и подписки в Remnawave: [синхронизация](remna-sync.md), кнопка есть прямо на экране восстановления.

Командой на сервере:

```sh
sudo stealthnet restore /root/stealthnet-backup-20261118-040000-auto.tar.gz.enc
```

Команда проверит копию, спросит пароль копии (или возьмёт из `SN_BACKUP_PASSWORD`) и подтверждение, остановит панель, восстановит базу и запустит панель снова. Части из Telegram передайте первой частью (`…tar.gz.enc.part001`) — команда соберёт их сама. Без вопросов: `sudo stealthnet restore --yes файл`.

### Копия перед обновлением

Перед каждым обновлением сервер отдельно сохраняет копию базы `pg_dump` и файла `deploy/.env` в папку `deploy/backups` (три последние). Ею пользуется само обновление, чтобы вернуть прежнюю версию при сбое.

Отдельно сохраните файл `deploy/.env`: в нём `SN_SECRET_KEY`, без которого не расшифровать ключи платёжек из копий без пароля.
