# Внешние модули

Внешний модуль — отдельная программа, которая дополняет панель: шлёт клиентам свои сообщения, выгружает оплаты в CRM, показывает свой отчёт и так далее. Модуль работает на вашем сервере или где угодно, на любом языке. Панель не запускает его код и не даёт ему доступа к базе: она только шлёт модулю события с подписью и выдаёт ключ API с правами, которые оператор подтвердил при установке.

Модуль подключается одним из двух способов:

- **Файл описания (JSON).** Модуль работает на вашем сервере или где угодно, а оператор загружает его описание в «Модули → Установить модуль». Об этом способе — разделы ниже, от «Как устроено» до «Установка, обновление, удаление». Готовый пример — [examples/module-hello](../examples/module-hello).
- **Архив (zip).** В архиве описание и готовый образ Docker. Оператор загружает архив в ту же кнопку, и панель сама запускает модуль контейнером на своём сервере: без SSH, своего HTTPS и копирования ключей. Об этом способе — раздел [«Модуль в архиве»](#модуль-в-архиве).

## Как устроено

1. Оператор загружает файл описания. Панель проверяет его и показывает человеческими словами: какие события будут уходить модулю, какие права получит его ключ, куда уходят события, есть ли у модуля своя страница.
2. После подтверждения панель выпускает ключ API (`snk_…`) и секрет подписи (`whsec_…`) и показывает их один раз. Оператор передаёт их модулю, например в переменных окружения.
3. Когда происходит событие, на которое подписан модуль, панель шлёт его на адрес модуля запросом `POST` с подписью.
4. Модуль обращается к API панели своим ключом: читает клиентов, пишет им в бот и так далее — в пределах подтверждённых прав.
5. Если у модуля есть страница, она открывается внутри админки, а модуль узнаёт, кто из администраторов её открыл.

Устанавливать, обновлять и удалять модули может администратор с правами «Модули» и «Настройки», и только из своей сессии в админке: ключом API этого не сделать. Выключить модуль и поменять его настройки можно с правом «Модули».

## Файл описания

```json
{
  "format": 1,
  "id": "hello",
  "name": "Привет",
  "version": "1.0.0",
  "author": "Студия Пример",
  "description": "Здоровается с новыми клиентами в боте и благодарит за оплату",
  "site": "https://example.com/hello",
  "webhook": "https://hello.example.com/stealthnet/events",
  "events": ["client_registered", "payment_paid"],
  "permissions": ["clients_read", "clients_write", "money"],
  "page": {
    "url": "https://hello.example.com/admin",
    "title": "Привет: журнал",
    "permission": "modules"
  },
  "settings": [
    { "key": "greeting", "type": "text", "label": "Текст приветствия", "large": true, "default": "Спасибо, что с нами!" },
    { "key": "thank_after_payment", "type": "flag", "label": "Благодарить за оплату", "default": true },
    { "key": "crm_token", "type": "secret", "label": "Токен CRM", "hint": "Из личного кабинета CRM" },
    { "key": "per_hour", "type": "number", "label": "Не больше сообщений в час", "default": 20 },
    {
      "key": "tone",
      "type": "select",
      "label": "Как обращаться",
      "options": ["formal", "friendly"],
      "labels": ["На вы", "На ты"],
      "default": "friendly",
      "required": true
    }
  ]
}
```

| Поле | Обязательно | Что это |
|---|---|---|
| `format` | да | Версия формата описания. Сейчас только `1` |
| `id` | да | Имя модуля: 2–40 символов, латиница в нижнем регистре, цифры и дефис, первая — буква. Не совпадает со встроенными модулями (`promo`, `referral`…). По `id` панель узнаёт модуль при обновлении |
| `name` | да | Название в списке модулей, до 60 символов |
| `version` | да | Версия модуля, любая строка до 30 символов |
| `author` | да | Автор, до 80 символов. Оператор видит его при подтверждении |
| `description` | нет | Что делает модуль, до 300 символов |
| `site` | нет | Сайт модуля, `https://…` |
| `webhook` | если есть `events` | Адрес, куда панель шлёт события |
| `events` | нет | На какие события подписан модуль — см. «События» |
| `permissions` | нет | Права ключа API модуля — см. «Права» |
| `page` | нет | Страница модуля внутри админки — см. «Страница в админке» |
| `client_card` | нет | Раздел модуля в карточке клиента, только в архиве — см. «Раздел в карточке клиента» |
| `bot` | нет | Кнопка модуля в главном меню бота, только в архиве — см. «Кнопка в боте» |
| `settings` | нет | Поля настроек, до 30 — см. «Настройки» |

Лишние поля и опечатки в именах полей — ошибка: панель покажет, что не так, со ссылкой на поле, например `events[1]: неизвестное событие «payment_done»`. Файл — не больше 64 КБ.

### Адреса

`webhook` и `page.url` — это `https://…` с доменом или публичным IP-адресом.

Адреса этого же сервера — `localhost`, `127.0.0.1`, `[::1]` и домены, которые на них ведут, — по умолчанию закрыты. Если модуль работает на том же сервере, что и панель, добавьте в `deploy/.env` строку `SN_EXT_MODULES_LOOPBACK=1` и перезапустите панель (`stealthnet restart`). Тогда на этот же сервер можно и без шифрования: `http://localhost`, `http://127.0.0.1` или `http://[::1]` с любым портом. В установке через Docker `127.0.0.1` — это контейнер панели, а не сам сервер: модуль должен работать в той же сети, что и панель, иначе ему нужен свой адрес `https://…`.

Без этой переменной панель не примет описание с таким адресом, а у модуля, установленного раньше, события на такой адрес не уходят: доставка сразу помечается «не доставлено» с подсказкой, без повторов. «Проверить связь» отвечает той же подсказкой, страница модуля не открывается. После перезапуска с переменной недоставленные события можно отправить снова из журнала.

Нельзя:

- адреса внутренней сети: `10.x`, `172.16–31.x`, `192.168.x`, `100.64–127.x`, `169.254.x`, `0.0.0.0`, `fc00::/7`, `fe80::/10` и другие служебные. Панель проверяет и имя домена при каждой доставке: если домен ведёт во внутреннюю сеть, событие не уйдёт;
- логин и пароль в адресе и часть после `#`;
- адрес самой панели.

Перенаправления (`301`, `302`…) панель не выполняет: такой ответ считается ошибкой доставки.

## События

Модуль получает только те события, на которые подписан, и только пока он включён. Каждое событие требует права на чтение этих данных: без права в `permissions` файл не примется.

События уходят, только пока ключ API модуля действует и у администратора, который его выпустил, есть право, нужное событию. Если ключ отозван или истёк, администратор отключён или у него забрали это право, такие события модулю не ставятся в очередь, а уже поставленные не отправляются: в журнале доставки видна причина. Служебные `ping` и `settings_changed` от этого не зависят.

| Событие | Когда | Нужно право | `data` |
|---|---|---|---|
| `client_registered` | Клиент зарегистрировался | `clients_read` | `client_id`, `source` (`bot`, `miniapp`, `web`, `admin`, `import`, `migration`), `start_param` — параметр ссылки или `null` |
| `client_blocked` | Клиент заблокирован | `clients_read` | `client_id`, `reason` |
| `client_unblocked` | Клиент разблокирован | `clients_read` | `client_id` |
| `client_telegram_linked` | Клиент с сайта привязал Telegram | `clients_read` | `client_id`, `telegram_id` |
| `payment_paid` | Оплата прошла | `money` | `payment_id`, `order_id`, `client_id`, `order_kind`, `amount`, `provider` |
| `payment_refunded` | Оплата возвращена | `money` | `payment_id`, `order_id`, `client_id`, `amount` |
| `order_fulfilled` | Покупка выдана | `clients_read` | `order_id`, `client_id`, `order_kind`, `subscription_id`, `days` — оплаченный срок в днях (0, если срока нет), `devices` — докупленные устройства |
| `subscription_created` | Подписка выдана | `clients_read` | `subscription_id`, `client_id`, `kind` (`paid`, `trial`, `gift`, `promo`, `manual`, `custom`) |
| `subscription_renewed` | Подписка продлена | `clients_read` | `subscription_id`, `client_id`, `expire_at` |
| `tariff_changed` | Тариф сменился | `clients_read` | `subscription_id`, `client_id`, `from`, `to` — номера тарифов |
| `subscription_status_changed` | Статус подписки изменился | `clients_read` | `subscription_id`, `client_id`, `from`, `to` (`active`, `limited`, `expired`, `disabled`) |
| `balance_changed` | Баланс изменился | `money` | `client_id`, `wallet` (`main`, `referral`), `kind` — причина, `delta` |
| `ticket_opened` | Новое обращение в поддержку | `support` | `ticket_id`, `client_id` |
| `ticket_answered` | Поддержка ответила клиенту | `support` | `ticket_id`, `client_id` |

`order_kind` — `new`, `renewal`, `change`, `top_up`, `trial`, `module`, `admin_grant`, `module_grant`. Суммы — `{"minor": 69900, "currency": "RUB"}`: `minor` в копейках или центах, для `XTR` — в звёздах. Время — ISO 8601 в UTC.

Ещё два служебных события приходят без подписки:

- `ping` — оператор нажал «Проверить связь» в карточке модуля. `data` пустой;
- `settings_changed` — оператор сохранил настройки модуля. В `data.keys` — какие поля изменились; сами значения модуль читает через API.

### Запрос с событием

```http
POST /stealthnet/events HTTP/1.1
Content-Type: application/json
User-Agent: stealthnet/0.1.0
webhook-id: evt_1532
webhook-timestamp: 1763467391
webhook-signature: v1,K5oZfzN95Z9UVu1EsfQmfVNQhnkZ2pj9o9NDN/H/pI4=

{"id":"evt_1532","type":"payment_paid","module":"hello","occurred_at":"2026-11-18T12:03:11.402Z","data":{"payment_id":812,"order_id":790,"client_id":41,"order_kind":"renewal","amount":{"minor":69900,"currency":"RUB"},"provider":"yookassa"}}
```

`id` у события постоянный: при повторной доставке он тот же. Служебные события получают `id` вида `msg_…`.

### Проверка подписи

Подпись устроена по открытой спецификации [Standard Webhooks](https://www.standardwebhooks.com/), поэтому подойдут и их готовые библиотеки.

1. Ключ — секрет без приставки `whsec_`, раскодированный из base64.
2. Строка для подписи — `{webhook-id}.{webhook-timestamp}.{тело запроса как есть}`.
3. Подпись — HMAC-SHA256 этой строки, в base64, с приставкой `v1,`. Сравнивайте её с заголовком `webhook-signature` за постоянное время.

Кроме подписи, модуль должен:

- отклонять события, у которых `webhook-timestamp` отличается от его часов больше чем на 5 минут;
- помнить `webhook-id` обработанных событий и не выполнять одно и то же дважды.

Пример на Python:

```python
import base64, hashlib, hmac, time

def check(secret: str, headers, body: bytes) -> bool:
    key = base64.b64decode(secret.removeprefix("whsec_"))
    msg_id = headers["webhook-id"]
    stamp = headers["webhook-timestamp"]
    if abs(time.time() - int(stamp)) > 300:
        return False
    signed = f"{msg_id}.{stamp}.".encode() + body
    expected = "v1," + base64.b64encode(hmac.new(key, signed, hashlib.sha256).digest()).decode()
    return any(hmac.compare_digest(expected, part) for part in headers["webhook-signature"].split(" "))
```

### Ответ модуля и повторы

- Любой код `2xx` за 10 секунд — событие доставлено. Тело ответа не нужно; первые 1000 символов попадут в журнал доставки.
- Всё остальное — ошибка: другой код, перенаправление, тайм-аут, нет соединения. Панель повторит через 30 секунд, 2 минуты, 10 минут, 30 минут, час, 3 часа и 6 часов. После восьмой неудачи событие помечается «не доставлено»: его можно отправить снова из журнала в карточке модуля — по одному или все недоставленные сразу.
- Порядок событий не гарантирован: повтор старого события может прийти после нового. Сверяйтесь с `occurred_at` и при необходимости с API.
- Модуль, который долго не отвечает, не тормозит ни панель, ни другие модули: доставка идёт отдельно для каждого модуля, не больше четырёх запросов к одному модулю одновременно.
- Отвечайте быстро, а долгую работу делайте после ответа.

## Права

Ключ API модуля работает как вход в админку с подтверждёнными правами. Права ключа не шире прав администратора, который установил модуль: при установке панель не даст подтвердить право, которого нет у самого администратора, а если администратора потом ограничат или отключат, ключ тоже сузится или перестанет работать, и события, для которых нужно снятое право, модулю уходить перестанут.

| Право | Что даёт |
|---|---|
| `clients_read` | Видеть клиентов, их подписки и историю |
| `clients_write` | Менять подписки и баланс клиентов, писать им, блокировать и удалять |
| `money` | Видеть оплаты, заказы и выручку, разбирать спорные оплаты |
| `refunds` | Возвращать клиентам деньги |
| `tariffs` | Менять тарифы и цены |
| `infrastructure` | Ноды, сквады и хосты Remnawave |
| `support` | Читать обращения и отвечать клиентам, в том числе с файлами |
| `marketing` | Промокоды, рассылки, рефералы, конкурсы |
| `modules` | Включать и настраивать встроенные модули |
| `settings` | Менять настройки панели, в том числе ключи платёжных систем и бота |

Права `admins` и `clients_login` (выдать клиенту пароль для сайта и снять ему вход по коду из приложения) модулю дать нельзя. Ключ модуля не может выпускать ключи, ставить и удалять модули, смотреть журнал доставки.

## API

Модуль передаёт ключ в заголовке `Authorization: Bearer snk_…`. Ключ работает, пока модуль включён: у выключенного и удалённого модуля запросы получают `401`.

Свои данные и настройки модуль читает так:

```http
GET /api/admin/ext-modules/me
Authorization: Bearer snk_…
```

```json
{
  "id": "hello",
  "name": "Привет",
  "version": "1.0.0",
  "enabled": true,
  "events": ["client_registered", "payment_paid"],
  "permissions": ["clients_read", "clients_write", "money"],
  "settings": {
    "greeting": "Спасибо, что с нами!",
    "thank_after_payment": true,
    "crm_token": "значение секретного поля или null",
    "per_hour": 20,
    "tone": "friendly"
  }
}
```

Остальное — тот же API, которым пользуется админка. Например:

| Запрос | Право | Что делает |
|---|---|---|
| `GET /api/admin/clients?limit=50` | `clients_read` | Список клиентов; условия — те же параметры, что в адресе страницы «Клиенты»: `tariff`, `category` (номера через запятую), `status`, `ends`, `ended`, `autorenew`, `source`, `lang`, `from`, `to` (RFC 3339), `paid`, `paid_from`, `paid_to`, `balance`, `telegram`, `email`, `bot_stopped`, `invited`, `invites` (`yes`/`no`), `utm`, `q`; условия про деньги — с правом `money` |
| `GET /api/admin/clients/segments` | `clients_read` | Сколько клиентов в каждом состоянии; с теми же условиями — внутри отбора |
| `GET /api/admin/clients/{id}` | `clients_read` | Карточка клиента |
| `GET /api/admin/subscriptions/{id}` | `clients_read` | Подписка |
| `POST /api/admin/clients/{id}/message` с `{"text": "…"}` | `clients_write` | Сообщение клиенту в бот |
| `GET /api/admin/payments` | `money` | Оплаты |

Все действия ключа записываются в журнал действий от имени модуля: в админке, в разделе «Журнал действий», они видны с названием модуля, а в истории клиента — подпись «Модуль «…»». Сам модуль журнал читать не может.

### Награды клиенту

Модуль может добавить клиенту дни к подписке, устройства или выдать личный промокод на скидку одним запросом. Каждая награда выдаётся ровно один раз на свой номер: повтор с тем же номером ничего не меняет и возвращает прежний результат.

```http
POST /api/admin/ext-modules/me/rewards
Authorization: Bearer snk_…
Content-Type: application/json

{"reference": "win:8f2c", "client_id": 41, "reward": {"kind": "days", "days": 3}, "label": "Приз в игре"}
```

| Поле | Что это |
|---|---|
| `reference` | Номер награды у модуля: до 80 знаков, латиница, цифры и `- _ . :` |
| `client_id` | Номер клиента |
| `subscription_id` | Необязательно: к какой подписке добавить дни или устройства. Без него — к основной живой подписке клиента |
| `reward` | `{"kind": "days", "days": 1–365}`, `{"kind": "devices", "devices": 1–10}` или `{"kind": "promo", "percent": 1–100, "valid_days": 1–365}` |
| `label` | Подпись до 100 символов: видна в истории клиента и в журнале |

Нужно право `clients_write`, для промокода ещё `marketing` и включённый модуль «Промокоды».

```json
{"reference": "win:8f2c", "status": "applied", "client_id": 41, "reward": {"kind": "days", "days": 3}, "subscription_id": 812, "expire_at": "2026-12-19T12:00:00Z", "extra_devices": null, "device_limit": null, "code": null, "valid_until": null, "applied_at": "2026-11-28T10:00:00Z"}
```

- `status`: `applied` — выдано сейчас, `duplicate` — уже было выдано раньше.
- Устройства прибавляются к числу устройств подписки. Если тариф продаёт доп. устройства и предел не превышен, это доп. устройство, которое входит в цену продления, иначе — лимит устройств подписки, заданный вручную.
- Промокод — личный: им может воспользоваться только этот клиент, один раз, при оплате в боте, кабинете или мини-приложении. Код приходит в ответе (`code`, `valid_until`), сообщить его клиенту — дело модуля, например через `POST /api/admin/clients/{id}/message`.
- Панель клиенту о наградах не пишет, кроме обычного уведомления о продлении подписки.

Ошибки приходят с кодом в `error.code`: `reward.no_subscription` — у клиента нет живой подписки, `reward.subscription` — подписка не его или завершена, `reward.mismatch` — номер уже занят другой наградой, `reward.in_progress` — эта награда сейчас выдаётся, `reward.unknown` — прошлая выдача оборвалась и неизвестно, дошла ли она, `reward.promo_off` — модуль «Промокоды» выключен. Если не ответила Remnawave, код ответа 503: повторите позже с тем же номером.

Узнать, чем кончилась выдача: `GET /api/admin/ext-modules/me/rewards/{reference}` — `state` (`applying`, `applied`, `failed`), `granted` и `error`.

## Настройки

Если в описании есть `settings`, в карточке модуля появляется форма — такая же, как у встроенных модулей. Модуль получает значения через `GET /api/admin/ext-modules/me`, а после каждого сохранения — событие `settings_changed`.

| Поле | Что это |
|---|---|
| `key` | Имя поля: латиница в нижнем регистре, цифры и `_` |
| `type` | `text`, `secret`, `number`, `flag`, `url` или `select` |
| `label` | Подпись поля, до 80 символов |
| `hint` | Подсказка под полем, до 300 символов |
| `required` | Без него настройки не сохранятся. По умолчанию `false` |
| `default` | Значение по умолчанию. У `secret` его не бывает |
| `large` | Только для `text`: большое поле до 4000 символов вместо 300 |
| `options`, `labels` | Только для `select`: значения и подписи к ним |

Секретные поля хранятся зашифрованными и в админке не показываются — только «задано» или нет. Модуль получает их значения в `GET /api/admin/ext-modules/me`.

При обновлении описания значения полей, которые остались с тем же типом, сохраняются; удалённые поля стираются.

## Страница в админке

Если в описании есть `page`, страница появляется в боковом меню админки под названием из `page.title`, пока модуль включён, а в карточке модуля — ссылка «Открыть страницу». Пункт меню видят администраторы с правом из `page.permission`; право `modules` для этого не нужно. Страница открывается во встроенном окне (`iframe` с `sandbox`): скрипты, формы и всплывающие окна работают, а доступа к самой админке, её сессии и кукам у страницы нет. Страница не может лежать на адресе самой панели. Открыть её могут администраторы с правом из `page.permission` (по умолчанию `modules`).

Панель добавляет к адресу страницы параметр `sn_token` — короткий подписанный токен. По нему модуль узнаёт, кто из администраторов открыл страницу:

- это JWT с алгоритмом HS256, подписанный тем же ключом, что и события (секрет без `whsec_`, раскодированный из base64);
- `iss` — `stealthnet`, `aud` — `module:<id модуля>`, `exp` — через 5 минут после выдачи;
- `admin_id`, `email`, `role` и `permissions` — кто открыл страницу и что ему можно.

Проверяйте подпись, `aud` и `exp`. Токен не даёт доступа к API панели — для API у модуля свой ключ.

Чтобы получить свежий токен, не перезагружая страницу, отправьте сообщение родительскому окну:

```js
window.parent.postMessage({ type: 'stealthnet:token' }, '*');
window.addEventListener('message', (event) => {
  if (event.data?.type === 'stealthnet:token' && event.data.token) {
    useToken(event.data.token, event.data.expires_at);
  }
});
```

Админка отвечает только своему встроенному окну и только на адрес страницы модуля.

## Установка, обновление, удаление

- **Установка.** «Модули → Установить модуль», выбрать файл, проверить, что получит модуль, подтвердить. Ключ API и секрет подписи показываются один раз.
- **Обновление.** В карточке модуля — «Обновить из файла». Панель покажет, что добавится и что уберётся, и попросит подтвердить заново. Ключ и секрет остаются прежними, права ключа меняются на новые.
- **Новый адрес.** Если в новом файле другой адрес для событий или страницы, окно покажет, какой адрес сейчас. Обновление пройдёт, только если подтверждён именно новый адрес (поля `webhook` и `page` в запросе установки), иначе отказ `ext_modules.confirm`. Запись `ext_module.updated` в журнале действий хранит старый и новый адрес (`moved`). Секрет подписи на адрес не уходит: туда идут только события с подписью и короткий пропуск администратора на страницу модуля.
- **Выключение.** Переключатель в списке модулей или в карточке. События перестают уходить (те, что ждали повтора, отменяются), ключ API не принимается. После включения ключ снова работает и уходят новые события; события, случившиеся за время выключения, модуль не получит.
- **Новые ключ и секрет.** В карточке модуля — «Выпустить новые». Старый ключ сразу отзывается, старый секрет перестаёт подходить.
- **Удаление.** Ключ API отзывается, секреты, настройки и журнал доставки стираются.

Журнал доставки хранится 14 дней.

## Модуль в архиве

Архив ставит владелец панели в «Модули → Установить модуль». Панель проверяет архив, показывает, что получит модуль и сколько ресурсов он займёт, и после подтверждения паролем отдаёт заявку помощнику на сервере. Помощник загружает образ и запускает контейнер. События, ключ API, настройки и страница в админке работают так же, как у модуля с файлом описания. Отличия описаны ниже.

### Что в архиве

ZIP до 500 МБ, внутри — только эти файлы, без папок:

| Файл | Что это |
|---|---|
| `module.json` | Файл описания, как выше, плюс раздел `run`. Адресов в нём нет: вместо `webhook` — `run.events_path`, вместо `page.url` — `page.path` |
| `image-linux-amd64.tar`, `image-linux-arm64.tar` | Образ модуля из `docker save`, обычный tar. Нужен хотя бы образ под процессор сервера оператора, иначе панель скажет, что сборки для него нет |
| `module.sig` | Подпись, необязательна. Её кладёт команда сборки |

```json
{
  "format": 1,
  "id": "node-autoinstall",
  "name": "Автоустановка нод",
  "version": "1.1.0",
  "author": "STEALTHNET",
  "page": { "path": "/", "title": "Установка нод", "permission": "infrastructure" },
  "settings": [{ "key": "remna_url", "type": "url", "label": "Адрес Remnawave", "required": true }],
  "run": {
    "port": 8095,
    "events_path": "/events",
    "health_path": "/healthz",
    "memory_mb": 128,
    "cpus": 0.5,
    "internet": true,
    "volumes": [{ "name": "data", "path": "/data" }]
  }
}
```

| Поле `run` | Обязательно | Что это |
|---|---|---|
| `port` | да | Порт, на котором модуль слушает внутри контейнера, от 1024. Слушайте `0.0.0.0`, а не `127.0.0.1` |
| `health_path` | да | Путь проверки работы: ответ `2xx` — модуль работает. После запуска помощник ждёт ответа до 90 секунд, потом панель спрашивает раз в минуту |
| `events_path` | нет | Куда слать события, например `/events`. Без него события не уходят, даже «Проверка связи» |
| `inbound_path` | нет | Куда панель пересылает запросы сторонних сервисов, например `/in` — см. «Входящий адрес» |
| `memory_mb` | нет | Предел памяти, от 64 до 2048 МБ, по умолчанию 256 |
| `cpus` | нет | Предел процессора, от 0.1 до 2 ядер с шагом 0.1, по умолчанию 1 |
| `internet` | нет | `true` — модулю нужен выход в интернет. По умолчанию `false`: модуль видит только панель |
| `volumes` | нет | До трёх папок данных: `name` — латиница в нижнем регистре и цифры, до 16 знаков; `path` — папка в контейнере. Нельзя `/`, `/proc`, `/sys`, `/dev`, `/tmp` и `/run` |
| `images` | да | Список образов с размером и sha256. Его заполняет команда сборки |

Пути `page.path`, `client_card.path`, `bot.path`, `events_path`, `health_path` и `inbound_path` начинаются с `/`, в них только латиница, цифры и знаки `/ - _ . ~`.

### Как запускается модуль

- **Пользователь и файлы.** Контейнер `sn-mod-<id>` работает от пользователя `10100`, а не от того, что указан в образе. Корень только для чтения, `/tmp` — 64 МБ в памяти. Писать можно только в папки из `volumes`: они принадлежат пользователю модуля и переживают перезапуск и обновление.
- **Чего у модуля нет.** Привилегий, сокета Docker, сети и папок сервера, открытых наружу портов. Есть пределы памяти, процессора и 256 процессов. Журнал — то, что модуль пишет в stdout и stderr, до 3 × 10 МБ.
- **Сеть.** Модуль видит только панель и другие модули. С `"internet": true` есть и выход в интернет. Базы панели и сети Remnawave в этой сети нет.
- **Переменные окружения** задаёт панель; свои переменные архив задать не может, а `ENV` из образа сохраняются:

| Переменная | Что это |
|---|---|
| `SN_PANEL_URL` | API панели изнутри: `http://stealthnet-panel:8080` |
| `SN_PUBLIC_URL` | Внешний адрес панели, например `https://example.com` |
| `SN_MODULE_ID` | `id` модуля |
| `SN_API_KEY_FILE` | `/run/secrets/sn_api_key` — файл с ключом API `snk_…` |
| `SN_SIGNING_SECRET_FILE` | `/run/secrets/sn_signing_secret` — файл с секретом подписи `whsec_…` |

- **Ключ и секрет.** Панель выпускает их сама и кладёт файлами с правами 0400, оператор их не видит. Читайте их при старте. Когда оператор нажимает «Выпустить новые», файлы перезаписываются, а модуль перезапускается.
- **События** приходят на `http://sn-mod-<id>:<port><events_path>` с той же подписью, что у модулей с файлом описания.
- **Обновление и откат.** Обновление — новый архив с тем же `id`. Помощник запускает новую версию с теми же папками данных. Если она не ответила на проверку за 90 секунд, возвращает прежнюю. Состояние, журнал и кнопки «Перезапустить», «Обновить из архива», «Удалить модуль» — в карточке модуля.
- **Удаление.** При удалении ключ отзывается, контейнер и образы убираются. Папки данных остаются, если оператор не отметил «Стереть данные». Повторная установка их подхватит.

### Страница модуля

Страница открывается через панель по адресу `/m/<id>/<пропуск>/` на домене панели, своего HTTPS модулю не нужно. `<пропуск>` — подпись панели, привязанная к администратору и его входу; при выходе администратора он перестаёт работать. Адрес начинается с `page.path`, панель добавляет к нему `sn_token`, как у обычной страницы.

- **Адреса только относительные.** `app.js`, а не `/app.js`; `api/state`, а не `/api/state`: префикс у каждого администратора свой. Если нужен абсолютный путь, возьмите префикс из заголовка `X-Forwarded-Prefix`.
- **Своего источника у страницы нет.** Она открывается во фрейме с `sandbox` без `allow-same-origin`, и панель добавляет к каждому ответу `Content-Security-Policy: sandbox …; frame-ancestors 'self'`. Поэтому куки, `localStorage`, `sessionStorage` и `history.replaceState` недоступны: оборачивайте их в `try`. Запросы страницы к своему API кросс-доменные, ответы CORS и `OPTIONS` даёт панель.
- **Кто открыл.** В каждом запросе к модулю есть заголовок `X-StealthNet-Admin` — JWT с теми же полями и тем же ключом, что `sn_token`, на 5 минут. Проверяйте подпись, `aud` и `exp`. `Authorization` из страницы доходит до модуля как есть, кук панели модуль не получает.
- **Ответы.** Панель вырезает из ответов модуля `Set-Cookie` и другие заголовки, кроме нужных для страниц. Перенаправление на путь с `/` получает префикс. Перенаправление на внешний адрес закрыто.
- **Ограничения.** Тело запроса — до 10 МБ, ответ идёт потоком. WebSocket не поддерживается.

### Раздел в карточке клиента

```json
"client_card": { "path": "/card", "title": "Бонус-игра", "permission": "clients_read" }
```

Панель показывает раздел в основной колонке карточки клиента, под «Рефералами», с заголовком `title`. Раздел видят администраторы с правом `permission` (по умолчанию `clients_read`). Внутри — фрейм с адресом `/m/<id>/<пропуск>/card?client_id=<номер клиента>&sn_token=…&sn_theme=dark` — так же, как у страницы модуля.

- Пропуск раздела открывает только `client_card.path` и адреса под ним: файлы и запросы раздела кладите под этот путь, например `card/app.js` и `card/api/…`. Страницу модуля и другие пути этот пропуск не открывает.
- Номер клиента приходит в адресе. Кто открыл карточку и что ему можно, модуль узнаёт из заголовка `X-StealthNet-Admin` в каждом запросе. Действия проверяйте по правам из него: например, менять что-то только с `clients_write` или только для ролей `owner` и `admin`.
- Высоту фрейма задаёт модуль: `window.parent.postMessage({ type: 'stealthnet:height', height: document.documentElement.scrollHeight }, '*')` после каждой перерисовки. Панель держит её от 48 до 4000 пикселей.
- Тема: параметр `sn_theme` (`light` или `dark`) и сообщение `{ type: 'stealthnet:theme', theme }`, когда администратор переключает тему. Фон страницы делайте прозрачным.
- Если действие в разделе меняет данные клиента в панели, отправьте `{ type: 'stealthnet:changed' }`: карточка обновит историю.

### Кнопка в боте

```json
"bot": { "button": "🎮 Игра", "path": "/bot/screen" }
```

В главном меню бота появляется кнопка с надписью `button` (до 32 символов). Где она стоит, оператор меняет в «Настройки → Бот», вкладка «Порядок кнопок»: там все кнопки внешних модулей — одна ячейка «Кнопки внешних модулей», её же можно скрыть. Нужно право `clients_read`.

Когда клиент нажимает кнопку, панель шлёт модулю на `bot.path` подписанный запрос, как событие, с типом `bot_screen`:

```json
{"id": "scr_6f1d…", "type": "bot_screen", "module": "game", "occurred_at": "2026-11-28T10:00:00Z", "data": {"client_id": 41, "telegram_id": 5093118422, "locale": "ru", "first_name": "Алексей"}}
```

Модуль отвечает за 4 секунды экраном:

```json
{"text": "🎮 <b>Игра</b>\n\n👉 Ваши попытки: 5", "buttons": [[{"text": "🕹️ Играть", "web_app": "https://game.example/"}]]}
```

- `text` — HTML, как в Telegram: `<b>`, `<i>`, `<u>`, `<s>`, `<a href>`, `<code>`, `<pre>`, `<blockquote>`, `<tg-spoiler>`, `<tg-emoji>`. Остальные теги показываются как текст. До 3500 символов без разметки.
- `buttons` — до 6 рядов по 3 кнопки. У кнопки `text` до 64 символов и ровно одно из: `web_app` — мини-приложение по `https://`, `url` — ссылка `https://` или `tg://`.
- Панель сама добавляет кнопку «Главное меню».
- Если модуль не ответил, ответил ошибкой или экран не прошёл проверку, клиент видит «Раздел сейчас недоступен. Попробуйте через минуту.» (текст меняется в «Тексты и кнопки»), а причина пишется в журнал панели.

### Входящий адрес

Сторонний сервис может слать модулю запросы на адрес панели:

```
https://<панель>/api/ext/<id>/<путь>  →  http://sn-mod-<id>:<port><inbound_path>/<путь>
```

- Методы `GET`, `POST`, `PUT`, `PATCH`, `DELETE`, тело до 1 МБ, ответ модуля до 1 МБ, ждём до 10 секунд.
- Модулю уходят `Content-Type`, `User-Agent`, `Accept`, `Authorization` и заголовки `X-…`, кроме `X-Forwarded-…`, `X-Real-IP` и `X-StealthNet-…`. Панель добавляет `X-Forwarded-For` с адресом отправителя, `X-Forwarded-Proto`, `X-Forwarded-Host` и `X-Forwarded-Prefix: /api/ext/<id>`. Кук модуль не получает.
- Из ответа модуля возвращаются код, `Content-Type`, `Retry-After` и `Cache-Control`.
- Панель запрос не проверяет: подпись и права отправителя проверяет сам модуль.
- Пути с `..` и закодированными `%2e`, `%2f` не пересылаются. Выключенный модуль и модуль без `inbound_path` отвечают 404.

### Сборка архива

```sh
docker save -o module/image-linux-amd64.tar my-module:1.1.0-amd64
docker save -o module/image-linux-arm64.tar my-module:1.1.0-arm64
stealthnet module pack module --key signing.key --out my-module-1.1.0.zip
```

`stealthnet module pack <папка>` берёт `module.json` и образы из папки и считает их размер и sha256. Затем собирает zip и проверяет его тем же кодом, что и установка. С `--key` архив подписывается. Ключ создаёт `stealthnet module keygen <файл>`: файл не перезаписывается, сохраните его в менеджере паролей. Команды есть в бинарнике и образе панели, например `docker run --rm --user "$(id -u):$(id -g)" -v "$PWD:/w" -w /w ghcr.io/stealthnet-app/stealthnet-rw-system:main module pack module --key signing.key`.

Подпись проверяется по открытому ключу:

- ключ STEALTHNET встроен в панель — архив помечается «подпись проверена»;
- архив без подписи или с чужим ключом владелец может поставить, только отметив, что доверяет автору;
- если подпись не сходится с `module.json`, архив не ставится.
